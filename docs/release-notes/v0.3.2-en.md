# Renewlet v0.3.2

Renewlet v0.3.2 adds centralized calendar subscription management and improves loading when you have many subscriptions. Settings navigation and common dialogs are also more stable while content loads.

---

## Read Before Upgrading

Cloudflare one-click deploy users should still upgrade from the generated repository by running `Sync Renewlet Upstream`. Do not click the one-click deploy button again. If an older generated repository does not have this entry yet, add it once from the [Cloudflare deploy documentation](https://github.com/zhiyingzzhou/renewlet/blob/main/docs/cloudflare-workers-deploy.md#existing-one-click-deploy-users).

If you configured `RENEWLET_CUSTOM_HEAD_SCRIPT`, replace it with `RENEWLET_CUSTOM_HEAD_HTML` before upgrading. The old variable has been removed. The new variable accepts complete Head HTML and should only contain code you trust. Restart Docker after changing it; rebuild and redeploy Cloudflare. If you never used this setting, no action is needed.

---

## New Features

- Settings now provides one place to manage calendar links for all renewals and individual subscriptions, including copying, opening, regenerating, and revoking them.
- Add to Calendar now clearly separates continuous syncing from one-time additions.
- Custom Head now accepts complete HTML fragments, including scripts, styles, and meta tags.

## Improvements

- Subscription lists, filters, statistics, calendars, and exports do less redundant loading as your data grows.
- Edit, renewal, details, calendar, and import dialogs keep their layout while loading instead of appearing blank or shifting.
- Settings waits for delayed sections to finish loading before scrolling to them, so the first navigation no longer lands on the wrong section.

## Fixes

- Deleting a subscription now also revokes its dedicated calendar link.
